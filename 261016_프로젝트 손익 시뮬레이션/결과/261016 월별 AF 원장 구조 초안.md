# 월별 A/F 원장 구조 초안

- 작성일: 2026-10-16
- 상태: 초안. 정책 항목(5장)은 사용자·경영기획팀 결정 전까지 확정하지 않는다.
- 근거
  - 7월 마감본의 월별 시트 구조
  - `결과/261016 대표3타이틀 계산경로·필드매핑.md`
  - `결과/261016 R1 원본대사 이슈로그.md`
- 범위: 프로젝트 단위 원장이다. 판관비·영업외·연결조정은 회사 단위 별도 레이어로 두고 이 원장에 넣지 않는다(R1 원칙 유지).

## 1. 왜 바꾸는가

R1은 프로젝트 × FY × 계정 합계만 갖고 있다. 그래서 다음 세 가지를 할 수 없다.

1. 어느 달까지가 실적이고 어디부터가 추정인지 구분하지 못한다. R1 350건이 모두 `Baseline`이다.
2. 다음 달 마감본이 오면 7월 기준값을 덮어쓸 수밖에 없다. 기준월별 이력이 남지 않는다.
3. 방영일·단가를 바꾸는 시뮬레이션을 할 수 없다. 월별 원천이 없기 때문이다.

원본은 이 문제를 "실적 월은 수식을 지우고 값을 입력, R/S는 BL 수식을 실적 합계로 교체, 손상은 AD를 AE에 값 복사"하는 수작업으로 해결한다. 이 수작업 때문에 I-07, I-08, I-13, I-15 같은 불일치가 생긴다. 이 초안은 그 수작업을 데이터 키와 상태 값으로 바꾸는 것이 목적이다.

## 2. 원장의 단위(그레인)와 키

한 행은 **"어느 기준판에서, 어느 프로젝트의, 어느 달, 어느 계정 금액이, 실적인지 추정인지"**다.

| 키 | 예시 | 설명 |
|---|---|---|
| `snapshot_id` | `2026-07_CLOSE_R0` | 기준판. 기준월 + 판 종류 + 리비전 |
| `project_id` | `P0017` | R1 Project_ID를 그대로 쓴다. 이름은 조인에 쓰지 않는다 |
| `period` | `2026-08` | 손익이 귀속되는 달(YYYY-MM) |
| `account` | `판권상각비` | R1 계정 12개. 아래 3장의 하위 계정 포함 |
| `sub_account` | `정기상각/구간2`, `Netflix` | 선택. 상각 구간, 플랫폼 등 |
| `af` | `A` / `F` | 실적/추정. 아래 규칙으로 자동 결정 |
| `source` | `7월마감본!1.제작!AW42` | 값의 출처. 원본 셀 또는 입력 화면 |

금액(`amount`, 억원, 원가는 비용 +/환입 −)과 함께 다음 속성을 둔다.

- `calc_basis`: 원본 값 / 원본 수식 / 모델 계산 / 수기 조정
- `note`
- `created_at`, `created_by`

`af`는 사람이 고르지 않는다. **`period`가 기준판의 마감월 이하이면 A, 초과이면 F**다. 예를 들어 `2026-07_CLOSE` 판이면 2026-07까지가 A다. 원본의 "7월까지 값, 8월부터 수식"과 같은 경계다.

## 3. 테이블 구성

| 테이블 | 한 행의 의미 | 주요 필드 | 원본 대응 |
|---|---|---|---|
| `snapshot` | 기준판 1개 | snapshot_id, 마감월(close_month), 판 종류(CLOSE/FORECAST/SIM), 원본 파일명·해시, 상태(작성중/잠금/폐기), 이전판 id | 월마감 송부 파일 1개 |
| `project_master` | 프로젝트 1개(판별) | snapshot_id, project_id, 이름, Captive 구분, 기준 FY, 방영 시작·종료일, 회차, 회당 제작비, 청구표제비, 독점/조합, 플랫폼, R/S율 | 라인업, 타이틀정보 |
| `pl_ledger` | 위 2장의 원장 행 | 2장 키 + amount, af, calc_basis | 1.제작·2.협찬·3-1·3-2 월 열, 상각raw |
| `amort_schedule` | 상각 구간 1개 × 월 | project_id, 구간 번호, 회차 수, 취득가, 상각개월, 정기/가속/절감 금액, 월말 잔존 | 상각raw 정기·가속 행 |
| `impairment_event` | 결산일별 손상 판단 1건 | project_id, 결산일, 경과월수, 경험률, 미실현 손익, 장부가, 계산 손상액(AD), **확정 손상액(AE)**, 확정자, 확정일 | 가속상각 시트 블록 |
| `rs_settlement` | 프로젝트 R/S 1건 | project_id, 산식 유형(표준/예외 id), 정산대상손익, R/S율, **계산 R/S**, **확정 R/S**, 인식월, 확정 여부, 근거 문서 | 프로젝트손익 BL·BQ, 1.제작 R/S 행 |
| `policy` | 정책 값 1개 | **namespace**(R1_TEMPLATE / WEBAPP_R5 / SOURCE_2607), policy_id, 값, 상태(적용/대기/승인), 승인자 | R1 04 시트, 웹앱 P04~P07 |
| `variance_log` | 판과 판 사이 차이 1건 | 이전 snapshot, 새 snapshot, project_id, period, account, 차이, 원인 분류(실적 확정/추정 변경/계약 변경/오류 수정) | 없음(신규) |

`policy`에 namespace를 둔 이유는 인수인계 문서의 경고 때문이다. R1의 P01~P05와 웹앱의 P04·P05·P07은 서로 다른 코드북이다. ID만으로 섞이지 않게 한다.

## 4. 마감 잠금과 판 전환 규칙

### 4.1 판 종류

- `CLOSE`: 월마감 송부본을 그대로 옮긴 판이다. 경영기획팀 파일이 정답이고, 우리는 수정하지 않는다.
- `FORECAST`: CLOSE 판을 복사한 뒤 F 구간만 고친 판이다. 예를 들어 사업기획이 방영일 변경을 반영한 전망이다.
- `SIM`: 시뮬레이션용 임시 판이다. 저장할 수는 있지만 보고 기준값으로 쓰지 않는다.

### 4.2 잠금

- CLOSE 판은 만들고 대사가 끝나면 `잠금` 상태가 된다. 잠금 판의 행은 수정할 수 없다. 고쳐야 하면 리비전(`_R1`)을 새로 만든다. 이전 판은 지우지 않는다(CLAUDE.md 파일 규칙과 같은 원칙).
- FORECAST·SIM 판에서는 **A 행을 수정할 수 없다**. 기준판 마감월 이하는 실적이므로, 방영일이나 단가를 바꿔도 F 구간만 다시 계산한다. 원본에서 7월 실적 셀이 값이라 바뀌지 않는 것과 같은 동작이다.

### 4.3 다음 달 마감본이 들어올 때 (예: 2026-08_CLOSE)

1. 새 CLOSE 판을 만든다. 7월판을 복사하지 않고 8월 송부 파일에서 새로 추출한다.
2. 2026-08 행이 F에서 A로 바뀐다.
3. 7월판과 8월판을 같은 키로 비교해 `variance_log`에 남긴다. 2026-08 행의 차이는 "추정 → 실적 확정"으로 분류한다. 2026-07 이전 행에 차이가 있으면 "과거 실적 수정"으로 따로 분류해 경고한다. 원래 바뀌면 안 되는 구간이기 때문이다.
4. 7월판은 그대로 남는다. 경영진 보고에서 "7월 기준 전망 대비 8월 기준 전망" 비교가 가능해진다.

### 4.4 R/S와 손상의 확정 처리

원본의 수작업 세 가지를 상태 값으로 바꾼다.

| 원본 수작업 | 원장 처리 |
|---|---|
| R/S 인식월이 실적 구간이 되면 1.제작 R/S 셀에 값 입력 | `rs_settlement.확정 여부 = Y`, `확정 R/S` 입력. 손익에는 확정 R/S만 들어감 |
| 실적이 확정된 타이틀은 BL 수식을 `=SUM(BM:BO)`로 교체 | 교체하지 않는다. `계산 R/S`는 계속 계산하고, `확정 R/S`와의 차이를 진단값으로 보여줌 |
| 손상 AD를 AE에 값 복사 | `impairment_event.확정 손상액`에 확정자·확정일과 함께 기록. 계산값과 확정값이 다르면 경고 |

이렇게 하면 경도를기다리며(계산 2.06억 vs 확정 0.23억), 미혼남녀(0.68 vs 0.65), 아파트 손상(8.671 vs 8.704)처럼 지금은 숨어 있는 차이가 항상 보인다. 손익 숫자 자체는 원본과 같다. 확정값을 쓰기 때문이다.

## 8. 구현 순서 제안

1. 대표 3개 타이틀만 7월판 `pl_ledger`·`amort_schedule`·`rs_settlement`·`impairment_event`로 엑셀 시트에 채운다. 원본에서 자동으로 추출하는 스크립트를 쓰고, 원본은 읽기만 한다.
2. 월 → FY 합계가 R1과 일치하는지(T1-1, T2-1, T3-1) 확인한다.
3. 8월 마감본이 있으면 같은 방식으로 8월판을 적재해 판 전환(4.3)을 시험한다. 없으면 7월판을 복사해 8월 행만 A로 바꾼 가상 판으로 시험한다.
4. 통과하면 47개 전체로 넓히고 R1을 R2로 고친다. 이때도 R1 파일은 덮어쓰지 않는다.
